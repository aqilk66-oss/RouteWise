# RouteWise — Production Deployment, Domain & HTTPS Architecture (Stage 28)

## 1. Executive Summary & Hosting Target
RouteWise is an enterprise Multi-Page Application (MPA) built with React 19, Vite, Tailwind CSS, Leaflet GIS, and Firebase Firestore/Authentication.
The platform is optimized for deployment on **Firebase Hosting** and **Vercel Edge Network** with automated SSL/TLS provisioning, HTTP/2 multiplexing, immutable asset caching, and strict Content Security Policies.

## 2. Production Domain Configuration & DNS Setup

### 2.1 Custom Domain Provisioning (Apex & Subdomain)
To map the custom enterprise domain `routewise.app` or `portal.schooltransport.edu`:

| Record Type | Host / Name | Target / Value | TTL | Purpose |
| :--- | :--- | :--- | :--- | :--- |
| **A Record** | `@` (apex) | `199.36.158.100` (Firebase Hosting IP 1) | 3600 | Primary root traffic routing |
| **A Record** | `@` (apex) | `199.36.158.100` (Firebase Hosting IP 2) | 3600 | Redundant root traffic routing |
| **CNAME** | `www` | `routewise-prod-firebase.web.app.` | 3600 | Canonical subdomain redirect |
| **TXT Record** | `@` | `hosted-domain-verify=routewise-prod-...` | 300 | SSL/TLS domain ownership verification |

### 2.2 SSL/TLS & HTTPS Enforcement
- **Automated Certificate Authority**: Let's Encrypt / Google Trust Services managed automatically.
- **HSTS (HTTP Strict Transport Security)**: Enforced via `max-age=31536000; includeSubDomains; preload`.
- **Insecure Redirection**: All unencrypted HTTP port 80 requests automatically execute a 301 Permanent Redirect to HTTPS port 443.

## 3. Production Caching & Edge Delivery Strategy

```text
Browser Client
      ↓
Edge CDN Cache (Assets: 1 Year Immutable)
      ↓
HTML Shell (index.html: No-Cache / Must-Revalidate)
      ↓
Firestore & WebSocket Telematics (Direct Authenticated TLS Channels)
```

### 3.1 Header Policies Implemented
1. **Static Hashed Bundles (`/assets/**`)**:
   - `Cache-Control: public, max-age=31536000, immutable`
   - Content-addressed filenames generated by Vite guarantee immediate cache invalidation upon release of new code.
2. **Document Root (`/index.html` & MPA Routes)**:
   - `Cache-Control: no-cache, no-store, must-revalidate`
   - Guarantees users always receive the latest release tag upon page load.
3. **HTTP Security Headers**:
   - `X-Frame-Options: DENY` (Clickjacking defense)
   - `X-Content-Type-Options: nosniff` (MIME sniffing prevention)
   - `Referrer-Policy: strict-origin-when-cross-origin` (URL leakage protection)
   - `Permissions-Policy: geolocation=(self), microphone=(), camera=()` (Hardware boundary protection)
